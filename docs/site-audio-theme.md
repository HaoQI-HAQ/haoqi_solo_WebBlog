# 全站交互音效

首页与 Photography、Music、Contact、About 使用原创 Web Audio 合成短音，沿用 Work 的清冷玻璃接触声、微弱空气扫频与短尾音。音效只反馈明确操作，不为悬停、滚动或连续浏览制造声音；不添加背景音乐。

## 合成接口

`src/audio/siteSoundSynth.js` 导出 `synthesizeSiteSound(context, destination, type, at, pan = 0)`，与 Work 的合成器保持相同约定，返回 `{ end, stop(now) }`。它不创建 AudioContext、不加载网络素材、不注册事件，交互与默认开关由共享控制器管理。

| type | 声音 | 最长时间（含收尾） |
| --- | --- | ---: |
| `nav` | 单次玻璃轻触与短泛音 | 95 ms |
| `menu-open` | 上行空气扫频和轻泛音 | 150 ms |
| `menu-close` | 下行收束，低一级的短音 | 112 ms |
| `filter` | 更短、更轻的清亮点击 | 70 ms |
| `copy-success` | 两个温和上行确认音 | 179 ms |
| `home-enter` | 首次主动进入时的短玻璃双音 | 212 ms |
| `gallery-next` | 轻触，短扫频向右展开 | 93 ms |
| `gallery-prev` | 同样质感，短扫频向左收回 | 93 ms |

`gallery-next` 与 `gallery-prev` 在未指定 pan 时分别轻度向右和向左定位；调用方传入非零 pan 时以调用方为准。其他 Work 类型直接委托原有 `workSoundSynth.js`，不改动 Work 的声音参数。

所有新声音由正弦波与确定性的短噪声在本地实时生成，没有新增音频下载。最响的原始振幅低于 0.1，并进一步通过全站音效总线控制。声音结束或调用 stop 后，源、包络、滤波器、输出与立体声节点全部断开。背景页、静音及卸载时应由共享控制器主动停止活跃声音。

默认开启表示用户偏好默认打开。浏览器首次点击或按键后自动解锁声音，无需额外的 opt-in；在此之前的启动帧不会补播。`haoqi-site-sound` 保存后续的显式静音选择，旧 `haoqi-work-sound` 不迁入。Work 开场、底栏与各页左下播放器里的开关共用同一状态。

`SiteSoundProvider` 在 Router 外持有唯一 UI 音效设备，SPA 跳转不会重建。每次 Work 挂载只建立新的可见时钟会话，第二次访问仍能完整播放启动声。页面隐藏会挂起设备并停止声音；全站卸载才关闭。播放器真实播放时将提示音降至平时的 40%，不改变音乐播放器的音量、曲目或播放状态。小游戏保留自己的复古合成声部，只在开始游戏时建立设备，并受全站静音与局部开关双重约束。

`emitSiteSound` 用于真实动作的结果（例如照片打开/ESC 关闭、复制成功），`data-site-sound` 用于明确的单击控件。导航链接反馈短音，当前筛选、当前专辑和无效操作保持安静。多选标签取消也会反馈；搜索输入、音乐进度更新、滚动、悬停及小游戏连发不叠加 UI 提示音。

## 验证

`node .taste-skill/verify-site-synth.mjs` 在 Chromium OfflineAudioContext 中以 48 kHz 双声道渲染全部 8 个原创类型和一个 Work 回退类型，同时验证提前停止。检查非零输出、无削波、结束后静音、全部源结束、节点断开与相册方向声像。详细结果保存在 `.taste-skill/site-sound-qa/synth-results.json`。

2026-10-24 全站接入验证：54 项音效、播放器、Work、几何与游戏引擎回归；18 组新增声音离线渲染；1440 像素桌面与 320/390 手机真实浏览器操作。覆盖默认开启、首手势自动解锁、导航、完整 Work 启动与第二次访问、照片/游戏图片 ESC、筛选取消、键盘切换、复制成功与失败、真实音乐播放时提示音衰减、全站静音的刷新记忆与小游戏约束。SPA 各页始终共用一个 UI context；只有实际开始游戏后才新增其复古声音设备。播放器进度事件不会反复重建音量自动化。
