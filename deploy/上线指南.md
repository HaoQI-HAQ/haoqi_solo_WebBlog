# 本地发布候选与后续上线

当前只准备本地候选版本，没有选择托管平台，没有配置云账户或发布公网。网站代码采用多页 Vite 构建；本指南不预设供应商、平台套餐、价格或域名。

## 先准备可复现环境

使用 Node.js 24（`.nvmrc`、`.node-version` 与 `package.json` 已声明），从版本库还原依赖：

```powershell
npm ci
npm test
npm run verify:deploy
npm run verify:fonts
npm run verify:assets
npm run check:release
```

`npm ci` 按 `package-lock.json` 安装。不要用删除 lockfile 再安装的方式生成候选包。CI 会执行上述测试和完整构建，没有自动发布步骤。资源和字体检查会在 fresh checkout 缺少素材或授权说明文件时失败；当前新增的源文件和素材尚未保存到 Git 时，不能直接依靠远端 CI 获得它们。

真实 `.env` / `.env.*` 已忽略，只提交 `.env.deploy.example`。`VITE_*` 会写入公开浏览器代码，只能放公开 URL；密钥应留在托管平台的服务端配置或凭据管理中，不得放在本项目前端。

## 两种明确的媒体模式

### 完整包：目前的本地候选方案

```powershell
npm run build:full
npm run preview
```

打开终端给出的预览地址。`dist` 含六个 HTML 入口、站点资源、全部 `media` 和 `videos`；音乐和照片保持当前本地体验。

`npm run build:deploy` 使用 `.env.deploy`，媒体地址为空时同样生成完整包。不会因为未填写媒体域名而删除素材。`npm run build` 是普通 Vite 构建，也遵循相同媒体模式。

完整包体积较大。选定平台后必须核对整体大小、单文件上限及媒体公开范围，不能直接假设任一平台接受该包。

### 外置包：确定媒体服务以后再用

复制 `.env.deploy.example` 为 `.env.deploy`，填写实际的公开地址：

```dotenv
VITE_MEDIA_MODE=external
VITE_MEDIA_BASE=https://实际媒体服务地址
VITE_SITE_URL=https://实际网站地址
```

```powershell
npm run build:external
```

缺少媒体地址、非法协议、带账号/查询参数的地址会在构建前明确失败。只有构建清单 `deployment.json` 与当前外置配置匹配时，整理脚本才允许移除输出中的重媒体。它不会修改 `public` 源素材，也会拒绝源目录、越界路径和符号链接作为输出。

上传整个 `public/media` 和 `public/videos` 并保留目录结构，包括专辑图片、游戏宣传图、游戏库封面、占位 SVG、摄影及 Work 模型封面；不能只上传 MP3 / MP4。`public/assets`、favicon、robots 等站点资源保留在站点包中。

当前页面路由和资源使用根路径，保持 `VITE_BASE=/`。子目录托管需另行改造和验证，不仅是修改 Vite base。

## 本地检查与公开发布门禁

```powershell
npm run check:release
npm run check:release -- --public
```

默认命令检查必需文件、lockfile、Node 版本、源文件中的常见凭据格式，并生成 `logs/release-check/source-manifest.json`（文件列表、文本校验值、Git 未保存变化和待确认事项）。它不会输出匹配到的凭据值，不替代完整安全审计。缺少正式域名或托管时会列出待确认事项，本地准备仍可通过。

`--public` 是将来公开前的严格配置门禁：要求实际 HTTPS 站点地址，外置时要求实际媒体地址，以及干净的 Git 版本。示例域名不能用于公开预检。这个命令只检查准备状态，不执行上传、购买、注册、提交或推送。

### 音乐播放与维护

音乐收藏完整保留，不设置音乐授权状态门禁，也不自动删除、过滤或停播曲目。发布自检记录当前专辑和音轨数量，资源检查验证音源、封面与歌词路径。

浏览专辑时使用离线元数据；音频仅在明确播放后加载。更新本地曲目后运行 `node scripts/build-music-metadata.mjs`，再运行 `npm test` 与 `npm run verify:assets`。

## 形成可回滚版本

检查报告列出 Git 中的修改与未跟踪文件；它们必须进入经过审查的源版本，GitHub 构建才能获得本地新增的模块和素材。保留源版本、lockfile、构建时的公开变量（不含密钥）与对应 `deployment.json`。候选目录可放 `logs/release-候选名/`，这些目录已忽略，不混入源提交。

版本保存由项目维护者审查完成；脚本不会替代你提交、推送或发布。回退时按该源版本、Node 24 和 `npm ci` 重新构建，不依赖当前开发服务器。

还可生成独立的本地恢复包：

```powershell
npm run snapshot:source
# 如需连同全部媒体一起备份：
npm run snapshot:source -- --with-media
```

默认写到已忽略的 `release-artifacts/source-snapshots`，包含源码与轻量素材、逐文件校验及恢复说明；重音视频和大图片默认仅有哈希/路径清单，仍依赖本地原文件或单独备份。`--with-media` 才把这些媒体全部纳入。恢复时应解压到新的空目录，不能覆盖唯一工作副本。这份本地私有恢复包不自动形成 Git 提交，也不等同于公开部署产物。

## 选定平台后才做的在线验收

1. 确认实际站点与媒体 URL、HTTPS、公开访问范围、平台文件/流量限制。
2. 在实际站点域名测试跨域 GET/HEAD、CORS、正确 Content-Type；音视频拖动应验证 Range 和 206。公开图片用于 WebGL/Canvas 时也需正确跨域策略。`cos-cors.xml` 仅是旧的供应商样例，需按选定服务和实际站点域名调整。
3. 检查六个入口可直接刷新；不存在路径返回真实 404 状态并展示错误页。具体 HTTP 状态与重写规则由托管配置决定，本地错误页文件不能替代服务端状态验收。
4. 验证缓存、压缩、安全响应头、搜索与分享图信息；`VITE_SITE_URL` 有效时才生成正式 canonical 与 sitemap。
5. 真实 iOS/Safari、Android 和中低端设备验收 Work 过渡、照片放大、菜单、键盘与音频；最终公网链路再检查第三方链接和播放器。
6. 明确备份、候选版本与回滚步骤，再决定是否公开。

上述在线检查目前尚未执行；本地构建成功不代表公网性能或第三方平台可达性已通过。
